### Webpack

Webpack будує граф залежностей і збирає застосунок у bundle. Для цього у проєкті окремо налаштовані entry, output, loaders, plugins та dev-server.

Переваги:

- дуже гнучка конфігурація;
- велика екосистема loaders і plugins;
- зручний контроль усіх етапів збірки;
- добре підходить для складних або старих проєктів.

Недоліки:

- конфігурація довша;
- потрібно вручну налаштовувати loaders для TypeScript і SCSS;
- старт dev-сервера може бути повільнішим на великих проєктах.

### Vite

Vite у режимі розробки швидко запускає сервер і віддає модулі за потребою. Браузер завантажує потрібні модулі без попереднього повного bundle. Для production Vite використовує оптимізовану збірку.

Переваги:

- коротша конфігурація;
- швидкий старт dev-сервера;
- швидкий HMR;
- зручна робота з TypeScript і сучасними frontend-проєктами.

Недоліки:

- для нестандартних сценаріїв також можуть знадобитися plugins;
- міграція складного Webpack-проєкту може вимагати зміни конфігурації;
- production-результати потрібно перевіряти окремим build-командою.

Для невеликого SPA цього проєкту Vite зручніший у щоденній розробці через коротшу конфігурацію та швидкий dev-сервер. Webpack краще демонструє ручне налаштування loaders, plugins і повного процесу збірки, що також є важливою навчальною частиною лабораторної роботи.

Для повністю експериментального порівняння потрібно окремо заміряти:

- час виконання `npm start` і `npm run start:vite` до готовності сервера;
- швидкість HMR після зміни TypeScript або SCSS;
- час виконання `npm run build` і `npm run build:vite`;
- розмір файлів у `dist` і `dist-vite`.
